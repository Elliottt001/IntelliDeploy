## 输入和运行方式

同一句需求：

> 做一个私人笔记网站，登录后可以新增、修改、删除笔记，刷新页面和服务重启后内容仍在，不同账号互相看不到笔记。

通过项目的 `POST /api/evaluation/runs` 实际提交，串行 Baseline → Hybrid；每个任务独立应用、独立 Idempotency-Key。使用真实 DeepSeek、真实 GitHub 检索、原有 Worker、专用 Runner 和 Linux 测试目标。没有固定路线、替换生成器、用 fixture 产物或伪造成功 URL。

API 地址为 `http://127.0.0.1:9007`。公共请求参数为 `budget_units=10000000`、`target_id=paired-linux` 和各自的 `algorithm_mode`。使用 `deepseek-flash`；最终两任务的输出上限都是 32768，模型调用上限都是 128。项目重试、用量记录和预算门禁仍生效。普通用户默认模式未切换。

观察脚本采用同一追问策略：任务进入 WAITING_USER 时才提供预设回答，内容是使用平台统一登录、每个账号只访问自己的笔记、完整实现增改删与刷新/重启后的持久保存、界面使用默认方案且不增加其他功能。每个任务最多自动回答一次。最后一对中，Baseline 进入 WAITING_USER 并收到回答；Hybrid 在需求整理重试中失败，没有进入 WAITING_USER，也没有收到这条补充消息。起始一句话完全相同，实际追问过程有差异，不能将这对失败任务当作严格对齐的算法阶段性能样本。计时从提交前开始，包含追问、模型重试和排队等待；每 2 秒轮询，终态观测有约一个轮询周期的误差。

测试服务器是用户指定的内网 Linux AMD64 主机，仅用于测试。API/Worker 在本机运行，Linux Runner、BuildKit、测试镜像仓库和 Caddy 在服务器运行，使用现有 SSH GSSAPI 与转发。服务器有 8 CPU、约 31.1 GiB 内存。公网镜像访问受限时采用本机准备镜像后上传；没有修改企业 SSH 策略或用于生产部署。
