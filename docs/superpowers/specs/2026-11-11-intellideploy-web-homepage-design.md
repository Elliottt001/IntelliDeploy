# IntelliDeploy Web 首页设计

日期：2026-11-11

状态：设计已逐段确认，等待书面规格复核

设计来源：`/Users/bytedance/Downloads/IntelliDeploy-design-2026-11-10-2221/`

## 1. 目标

在现有 `web/` Next.js 应用中实现 IntelliDeploy 公开营销首页，严格还原 Figma 的视觉布局、浅深色主题和宽屏信息层级，同时使用真实业务文案、真实路由和真实后端数据。

本设计遵循以下原则：

- Figma 是视觉和布局基准，不是业务事实来源。
- 不复制设计稿中的拼写错误、心理健康模板文案、虚假统计、虚构评价或无来源品牌。
- 不使用生产占位数据、假应用、假价格、假支付成功状态或无法工作的按钮。
- 网页使用真正的响应式重排，不缩放 `2025px` Figma 画布。
- 首页所需的社区与定价数据接入真实后端；账户、订单和支付保持既有鉴权及资金安全边界。
- 前后端目标合同以 `docs/superpowers` 已确认的一期设计和计划为准，不能因当前实现不完整而缩减目标接口。

## 2. 范围

### 2.1 本规格包含

- `/` 公开营销首页。
- 当前创建页面从 `/` 迁移到 `/create`，保留已有创建行为。
- 首页导航、Hero、能力、Mibo、应用社区、交付流程、真实定价目录和 Footer。
- Figma 浅色与深色主题、手动切换、系统主题跟随及本地持久化。
- 桌面、平板和手机的响应式重排。
- 首页公共社区数据和公共 SKU 投影接口。
- 共享 OpenAPI/API Client 类型同步。
- 首页相关单元、接口、E2E、可访问性和视觉验收。

### 2.2 本规格不包含

- 支付宝、微信或 Stripe 的订单创建、签名通知、结算和额度入账实现。
- `/billing` 的完整购买、订阅、取消和订单查询流程。
- 创作者分成、提现或应用门票。
- Expo 手机端页面重做。
- 生成应用的业务流水线重构。

支付闭环继续遵循 `docs/superpowers/plans/2026-11-09-phase1-06-billing-acceptance.md` 的 `06-F2/F3`，并单独形成后续规格。首页不得另写第二套订单协议。

本规格中的手机适配仅指 Web 首页在手机浏览器中的响应式重排，不代表 `frontend/` Expo 原生客户端的页面实现。Expo 移动端包含登录、主界面、Mibo 对话、应用社区和我的产品等完整流程，应在 Web 首页完成后依据移动端 60 页设计稿单独形成规格和实施计划。

## 3. 已确认的产品决策

- Web 营销首页位于 `web/`，不使用 Expo Web 承载。
- `/` 是公开营销首页。
- `/create` 承载现有创建表单和 API 流程。
- Hero 和 Mibo 的主要 CTA 进入 `/create`。
- 应用社区入口进入 `/community`。
- 登录和注册进入 `/login`、`/register`。
- 已登录应用工作区继续使用 `/apps`。
- 首页首次跟随系统主题；用户手动切换后本地保存选择。
- 匿名首页只读取公共目录；余额、订阅、订单和用量保持登录鉴权。
- 视觉严格贴合 Figma，但业务内容必须真实、可验证。
- 支付闭环与首页分成连续但独立的规格。

## 5. 总体架构

继续使用现有 Next.js、React、Tailwind 和共享 API Client，不引入第二套前端运行时或新的 UI 组件库。

根布局只负责：

- HTML 语言和页面元数据。
- 字体声明。
- 主题初始化脚本。
- 全局设计令牌和基础样式。

营销首页主要使用 Server Components。只有主题切换、移动菜单和必要的展示动效使用 Client Components。社区与 SKU 数据在服务端读取后作为只读 props 下发，首屏不重复发起客户端请求。

## 6. 路由设计

使用 Next.js Route Groups 分隔营销页和现有产品页，但不改变公开 URL：

```text
web/app/
  layout.tsx
  (marketing)/
    page.tsx                  -> /
  (platform)/
    layout.tsx
    create/page.tsx           -> /create
    apps/page.tsx             -> /apps
    apps/[id]/page.tsx        -> /apps/:id
    community/page.tsx        -> /community
    community/[id]/page.tsx   -> /community/:id
    login/page.tsx            -> /login
    register/page.tsx         -> /register
```

当前 `web/app/page.tsx` 的创建逻辑迁移为独立 `CreateAppForm`：

- 保留本地草稿恢复。
- 保留提交幂等键。
- 保留现有 `api.createApp` 调用和成功跳转。
- 不在营销首页复制创建逻辑。

匿名用户可以进入 `/create` 并保留草稿。需要认证的提交进入登录流程，登录完成后安全返回 `/create`。`next` 参数只允许站内已登记路径，不能形成开放重定向。

## 7. 页面内容映射

### 7.1 导航

保留 Figma 的品牌、胶囊式导航、账户操作和主题按钮。导航项只指向真实页面或当前页面的真实区块。

### 7.2 Hero

保留超大标题、渐变光晕、Mibo 形象、主次 CTA 和宽屏视觉中心。主要 CTA 进入 `/create`，次要 CTA 进入 `/community` 或页面内真实能力区块。

### 7.3 能力条

Figma 中无法证明的用户数、增长率或成功率不展示。原统计卡片位置改为已实现或一期明确设计的产品能力，例如：

- 自然语言描述需求。
- 持续对话调整。
- 按验收项验证交付。
- 独立运行与数据空间。

能力文案不得把尚未真实验收的外部模型、云目标或支付渠道写成已经完成。

### 7.4 Mibo

Mibo 是 IntelliDeploy 的需求对话和创建助手视觉角色。该区说明需求输入、任务状态、业务追问和持续修改，不把动画进度当成实际任务进度。

### 7.5 应用社区

将设计稿 Appstore 视觉映射到真实应用社区：

- 入口使用 `/community`。
- 卡片读取真实 Publication。
- 只链接真实公开详情或可用入口。
- 无数据时显示空状态。
- 接口失败时显示诚实错误状态。

### 7.6 交付流程

原编辑推荐或用户评价区改为“从需求到可使用应用”的真实流程说明，保留杂志式构图和视觉层级，不虚构人物、媒体、客户或评价。

流程内容为：需求整理、实现路径、业务验证、部署交付和持续调整。具体状态必须与一期 Job/AppVersion/Instance 设计一致。

### 7.7 定价

定价卡只展示公共 SKU 接口可证明的字段：

- SKU 名称。
- 支付渠道。
- 币种和整数金额。
- 授予额度。
- 套餐或购买周期。

不展示未由后端配置的权益、折扣、原价、热门标签或无限额度。支付闭环完成前，不使用“立即购买”或“订阅成功”等文案。

### 7.8 Footer

只展示真实存在的产品入口、必要说明和版权信息。不放置空链接或未上线的社交媒体入口。

## 9. 响应式设计

### 9.1 大屏：`>= 1440px`

- 内容最大宽度约 `1744px`。
- 保留 Figma 的宽屏留白、双栏特性区和多卡片布局。
- 在 `2025px` 测试视口下对齐原始主要导线。
- 装饰素材使用稳定锚点，不依赖页面绝对坐标。

### 9.2 中屏：`768px - 1439px`

- 缩小横向留白。
- 多卡片区域改为两列或内容驱动网格。
- 复杂双栏按阅读顺序重新组合。
- 装饰元素重新锚定或裁切，不整体缩小桌面画布。

### 9.3 小屏：`< 768px`

- 单列信息流。
- 导航改为可访问移动菜单。
- Hero 文案先于 Mibo 视觉。
- 能力、流程和定价卡纵向排列。
- 主要阅读和操作不依赖横向滚动。
- 触控目标满足移动端尺寸要求。

实现使用 CSS Variables、CSS Modules、Grid、Flex、`clamp()` 和必要的容器查询。断点用于结构重排，不复制三套组件。

## 10. 主题与动效

主题规则：

1. 没有本地选择时跟随 `prefers-color-scheme`。
2. 用户手动选择浅色或深色后写入本地存储。
3. 在 React 水合前恢复主题，避免首屏闪烁。
4. 主题按钮具有明确的可访问名称和状态。

动效只用于 Mibo、背景光晕和区块进入等视觉表达。所有动效遵循 `prefers-reduced-motion`。任何任务阶段、部署进度或支付结果都必须来自后端状态，不能由定时动画推断。

## 11. 字体方案

字体源位于 `frontend/assets/fonts/`，其中包含来源记录和许可文件。Web 实现选择性复制允许分发且实际使用的字体到自身构建资源目录，不在运行时依赖 Expo 资产路径。

字体映射：

- Alibaba PuHuiTi 3.0：中文品牌标题与主要正文。
- Inter、Geist、Instrument Sans：导航、按钮、标签、数字和英文标题。
- Ibarra Real Nova：Figma 指定的杂志式衬线标题。
- Pixelify Sans：Figma 指定的像素风品牌点缀。
- PingFang SC：Apple 平台系统字体回退。

使用 `next/font/local` 自托管允许分发的字体。只加载页面实际需要的变量字体或少数字重，评估 WOFF2 和静态文字子集化，避免让首屏下载全部中文字体文件。

`PingFangUI.ttc` 来源于 macOS 私有系统资源，不提交、不复制到 Web 静态目录，也不作为可分发 Web 字体。Apple 设备通过系统 `PingFang SC` 字体族使用它。

保留 `FONT_SOURCES.md` 和适用的 OFL 许可说明。

从设计包选择首页实际使用的 Mibo、设备和装饰素材，复制到 `web/public/marketing/`，使用稳定的 ASCII 文件名并保留来源说明。

禁止：

- 把无关参考图、历史稿或垃圾桶区域素材带入产品。

完整浅色和深色首页 PNG 仅用于视觉对照与回归检查。

## 13. 数据合同

### 13.1 社区

首页使用既有匿名接口：

```http
GET /api/community/apps?limit=<bounded>
```

响应复用 `PublicationPage`。首页仅展示接口返回的公开字段，不读取收藏、最近使用、私有应用或账户数据。

### 13.2 公共 SKU

新增匿名只读接口：

```http
GET /api/catalog/skus
```

响应复用共享 `QuotaSku[]`：

```text
id
name
provider
currency
amount_minor
units
period
```

公共接口与登录后的 `GET /api/quota/skus` 复用同一查询函数和 `ProductSku` 数据源，只返回 `enabled=true` 的 SKU。它不增加另一张价格表，也不改变既有计费规则。

公共接口不得返回：

- 用户身份。
- 账户余额或预留额度。
- 当前订阅。
- 订单。
- Checkout URL。
- 商户配置、密钥或渠道内部字段。

### 13.3 金额显示

- `amount_minor` 始终是整数最小货币单位。
- 前端只使用 `Intl.NumberFormat` 格式化。
- 前端不计算折扣，不换算实时汇率，不生成下单金额。
- 后续下单必须由服务端根据 `sku_id` 重新核对价格、币种、渠道和可用状态。

### 13.4 支付合同依赖

后续支付规格继续使用已确认接口：

```http
POST /api/quota/orders
GET /api/quota/orders/{id}
GET /api/quota/subscription
POST /api/quota/subscription/cancel
```

订单价格、额度、周期和 Checkout URL 均由服务端产生。浏览器成功页不能发放额度，支付渠道通知必须经过签名、订单、金额和币种校验。

## 14. BFF 与鉴权边界

Web BFF 允许匿名转发的路径仅增加 `/api/catalog/skus`。现有匿名社区路径保持不变。

以下接口继续要求有效登录会话：

- `/api/quota/policy`
- `/api/quota/balance`
- `/api/quota/usage`
- `/api/quota/skus`
- `/api/quota/subscription`
- `/api/quota/orders`
- 所有应用、任务和个人库写操作

BFF 不向浏览器暴露上游 Bearer Token。修改请求继续执行同源校验。公共首页接入不能放宽其他路径白名单或认证条件。

## 15. 失败处理

首页使用独立的服务端数据结果处理社区和 SKU，单个动态区块失败不能阻止整个首页渲染。

### 社区

- 成功且有数据：展示真实 Publication。
- 成功但为空：展示明确空状态。
- 请求失败：显示“社区内容暂时无法加载”和真实社区入口。

### 定价

- 成功且有数据：展示真实 SKU 卡片。
- 成功但为空：显示“套餐暂未发布”。
- 请求失败：显示“套餐信息暂时无法加载”。

禁止使用硬编码价格、示例应用或旧缓存假装接口成功。服务端日志只记录请求关联信息和错误类型，不记录 Token、Cookie、账户数据或支付凭据。

## 16. 可访问性

- 使用语义化标题层级、导航、区块和列表。
- 图片根据用途提供有效替代文本或标记为装饰。
- 所有功能可通过键盘使用。
- 移动菜单打开后管理焦点，Escape 可关闭。
- 可见焦点样式符合主题。
- 文字和交互控件达到 WCAG AA 对比度目标。
- 不只使用颜色表达选中、错误或状态。
- 主题和动态区块变化使用适当的可访问状态，不制造冗余播报。

## 17. 测试策略

### 17.1 后端与共享协议

- 匿名用户可以读取 `/api/catalog/skus`。
- 只返回 `enabled=true` 的 SKU。
- 公共响应不含账户、订阅和订单字段。
- 公共和鉴权 SKU 接口使用同一数据源及共享转换逻辑。
- `amount_minor` 保持整数。
- 其他 `/api/quota/*` 路径仍拒绝未登录访问。
- OpenAPI 导出和 `packages/api-client` 生成类型无漂移。
- API Client 增加公共 SKU 读取方法，不手写重复响应类型。

### 17.2 Web 单元测试

- 主题初始化和手动选择持久化。
- 金额按币种正确格式化，不使用浮点价格计算。
- 导航和 CTA 路径正确。
- 空数据和错误状态不渲染假内容。
- `next` 参数只允许站内路径。

### 17.3 Playwright E2E

- `/` 可匿名访问。
- CTA 正确进入 `/create` 和 `/community`。
- 创建表单迁移后保留草稿、幂等键和成功跳转。
- 匿名提交进入登录流程，登录后回到 `/create` 且草稿仍在。
- 社区预览打开真实 Publication 路由。
