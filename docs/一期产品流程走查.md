# 一期产品流程走查与实施验收入口

日期：2026-11-10。检查对象为本轮修订后的PRD、技术设计、总计划与01—08子计划。此文件是文档流程走查，产品代码、云/模型/支付及原生客户端均尚未执行验收。

## 1. 一期范围与完成定义

保留Expo手机客户端（frontend），新增Next Web（web），共用FastAPI后端/Worker。用户应用为Web。A/B/C/D全包含，默认先完整检索和评分，不将搜索故障当作无可复用项目。平台托管在准备好的Linux/Sealos资源，提供常用身份/数据/文件/AI/搜索、对话调整、社区共享/副本、免费/套餐/购买额度与三支付。

实施完成不仅是文件存在：生成和调整必须核心需求/回归检查、真实部署入口及业务动作通过；管理操作必须观测资源状态；必需评测缺配置为NOT_RUN而非PASS。二期原生生成/变现/额外主动运维仍不在一期执行范围。

## 2. 用户主流程逐段走查

| 步骤 | 用户行为与可见结果 | 后端/Worker契约 | 实施与验收责任 |
| --- | --- | --- | --- |
| 1 登录 | 在Expo/Web登录；可保留未登录输入 | /auth JSON+Bearer，Web同源cookie；不暴露平台Key | 01-F1/F3、07-E1/E2；跨端同一用户 |
| 2 免费/套餐 | 看余额与默认费用规则，无需填写技术参数 | 注册唯一grant、GET quota/policy；周期维护发放 | 06-F1、03-D7；重复登录不重复领 |
| 3 描述需求 | 输入应用用途后发起，拿到可恢复任务 | POST apps+Idempotency-Key，事务创建App/Job，HTTP不运行模型 | 01-F3；重复点击同id，越权404 |
| 4 理解需求 | 只回答关键业务问题；其他细节自动推断 | 02-G6原文/事实/验收映射，WAITING_USER回复恢复同job | 02-G6、01-F3；原要求不漏项、默认私有 |
| 5 检索与选路 | 看简明“准备应用”，不选择技术路线 | 多查询实时GitHub+索引，兼容/评分，A优先，B/C评估，D保存否决理由 | 02-G3/G7；完整检索失败不能转D |
| 6 实现 | 可关闭客户端后回来查看 | run_pipeline冻结revision，源码工作区/来源commit/工具检查点持久 | 02-G2/G4/G5、03-D6、01-F2；Worker重启可核对恢复 |
| 7 构建与候选 | 无需手动启动/安装应用 | 固定镜像digest，独立runner启动候选和依赖，临时身份/数据 | 03-D2/D6、04-C1/C2；代码/环境隔离实际验证 |
| 8 功能验证 | 简明“验证功能”，失败可后台修复 | 所有核心ID动作/断言，重启读数据、两用户隐私、AI/搜索真实调用 | 03-D1/D6、04-C3；200/假数据不算成功 |
| 9 自动修复 | 正常情况下无需用户处理编译/部署错误 | 失败证据回同Agent，尝试/总预算共用；无法继续明确FAILED | 02-G4、03-D6；首次坏实现可自动修复，失败无假URL |
| 10 发布应用 | 最终获得真实“打开应用”入口 | 相同已测digest，准备运行槽/线上验证/切换入口/持久终态 | 03-D3/D4/D5/D6；两类目标真实访问 |
| 11 查看结果 | 交付卡、功能说明、用量、继续调整/发布 | GET app/job/report/artifact，业务报告与内部诊断分开 | 01-F3、05-W1、07-E1/E2/E3；跨端同id/版本 |
| 12 使用应用 | 浏览器操作并保存各自数据 | 私有入口单次code身份交换，文件/数据按实例和用户隔离 | 04-C1/C2/C3；未授权/跨用户拒绝，真实搜索来源 |
| 13 继续修改 | “加搜索”等自然语言调整，旧记录保留 | 新ADJUST job从当前源码/需求开始，保留回归；冻结写入迁移/恢复 | 02-G6、03-D6；未通过不替换旧版，恢复未知明确维护 |
| 14 社区发布 | 选SPONSOR/VISITOR和赞助上限，分享链接 | active/instance/publication版本一致；匿名访问按功能；上限由服务端执行 | 05-W2、04-C1、06-F1；不公开拥有者私有数据 |
| 15 使用与副本 | 访客直接使用同一实例，或创建自己的独立副本 | COPY复用固定来源代码/检查，新身份/数据/实例；实际部署验收 | 05-W3、03-D6；不复制账号/记录/Key，不随作者升级 |
| 16 停止与恢复 | 停止保留数据，补额度/手动恢复，查看实际状态 | 独立InstanceOperation+observed_state，非生成Job；按操作id轮询 | 03-D7、05-W1、07-E2；202不当运行成功 |
| 17 充值与订阅 | 三渠道购买，回客户端确认到账再继续 | 服务端订单/回调验签/周期唯一grant，PAUSED_QUOTA恢复同job | 06-F1/F2/F3、07-E2；返回成功页不发额度 |
| 18 删除与取消公开 | 明确删除数据范围，或取消分享 | 用户DELETE确认与资源记录；取消公开拒绝新匿名访问，保留实例拥有者权限 | 03-D7、05-W2；不误删其他实例数据 |

默认选择部署目标、预算和技术栈在后端完成。开发者评测可以指定已登记目标但不绕过自动路由，普通用户不提交云凭据。任务进度来自持久phase，不能伪造百分比或在候选就绪时显示交付成功。

## 3. 异常/恢复走查

| 情况 | 必须有的结果 | 验收位置 |
| --- | --- | --- |
| 核心业务信息不足 | WAITING_USER、少量业务问题，关闭/跨端后恢复 | 02-G6、01-F3、07-E2 |
| 模型不能整理有效需求 | 有界纠正后明确FAILED，不跳过清单 | 02-G6 |
| 用户要求一期不支持的原生生成 | 明确支持Web，业务追问是否接受，不冒充原生 | 02-G6 |
| GitHub限流/资料缺失 | 重试，未完成搜索保留可重试故障，不自动D | 02-G3/G7 |
| 搜到项目但环境不支持 | UNKNOWN继续获取证据，UNSUPPORTED评估其他复用，确实无合理复用才D | 02-G7 |
| 构建、候选健康或核心动作失败 | 分类证据驱动同一修复循环；超限制FAILED | 03-D6 |
| 平台或模型上游余额/Key故障 | UPSTREAM_UNAVAILABLE，由管理员诊断，不让用户充值自己的平台额度解决供应商402 | 02-G1、04-C3、08-O1 |
| 用户平台额度不足 | PAUSED_QUOTA保存状态，补额度后明确resume，不重扣已发生动作 | 06-F1、01-F3 |
| Worker或平台服务器中断 | 租约/检查点/ReleaseAttempt核对；旧Worker不能写发布终态 | 01-F2、03-D6、08-O1 |
| 数据迁移或上线检查失败 | 回滚旧入口/数据，无法证明恢复则维护+明确失败，不能谎称可用 | 03-D6 |
| 同时修改/停止/删除 | 共用互斥，409保留用户输入；先取消安全结束再管理 | 03-D7、01-F3 |
| 实例欠费或人工停止 | 停计算保留数据，用户补额度start恢复同版本；计量窗口幂等 | 03-D7、06-F1 |
| 实例所在目标失联 | observed状态未知/诊断待核对，不收费未经证实用量，不猜0 | 03-D7 |
| 支付重复或乱序通知 | 核对真实供应商对象、同交易/周期一次入账 | 06-F2/F3 |
| 赞助上限耗尽 | 能力请求拒绝/提示额度限制，访客不绕过上限；不公开作者数据 | 05-W2、04-C1、06-F1 |
| 清理时出现新版本/任务引用 | 执行前复查引用，取消清理；活跃/暂停/版本/社区资源保护 | 08-O2 |
| 客户端断线或登录过期 | 保存app/job/输入，回读现有状态，不创建重复任务 | 07-E1/E2、05-W1 |

## 5. 走查发现及本轮解决

| 发现 | 修订后的约束 |
| --- | --- |
| 需求只有schema，没有编译/覆盖入口 | 02-G6冻结revision及原文/验收映射，调整回归保留 |
| 源码完成与候选运行、修复脱节 | 03-D6单一run_pipeline及候选runner，报告绑定已测digest |
| 停机后没有start与状态采集 | 03-D7独立操作/维护租约/分钟计量，客户端轮询真实结果 |
| 索引依赖手工语料与不明确兼容性 | 02-G7原子更新/实时补证据/首批环境，仍保留四路线 |
| 只部署用户应用，平台自身缺发行方案 | 08-O1生产服务、管理CLI和健康/日志，08-O2引用保护清理 |
| 四个示例不能判断需求覆盖与产品质量 | 07-E4至少12例+人工复核，flow/faults与真实指标分开 |
| Web请求重复/api前缀与SSE命名监听不一致 | 07-E1空baseUrl+完整path，01-F3/05-W1统一event:job |
| 上游402被当用户额度不足 | 区分供应商故障与平台余额；请求为空也按实际计费证据处理 |
| job预算与能力调用重复预留 | 父Reservation+子UsageEntry；首次执行/恢复规则统一 |
| 社区版本引用与运行版本可能不同 | 发布必须当前已测版本，成功调整同步Publication，副本固定来源 |
| 测试预期D与实际适合复用的项目冲突 | expected_route只作参考，实际优先复用，过时预期标记/补真实D样本，不强制路由 |
| 多份验收case字段route/checks不同 | 输入统一expected_route/core_checks；旧报告只转换作历史读取 |

文档流程走查结论：上述六项及本轮发现的接口冲突已在计划中给出责任任务与验收，主流程/恢复路径能追溯到实现位置；这只说明方案衔接已定义。实际能力、生成质量、运行隔离及费用仍需执行任务和真实评测证明，不承诺没有实施阶段新问题。
