## 1. 环境与数据库

使用Python3.13、Node24、npm及Docker/Compose。本机已建立.venv和带持久卷的独立PostgreSQL17；新环境执行：

```bash
uv python install 3.13
uv venv --python 3.13 .venv
uv pip install --python .venv/bin/python -r backend/requirements.txt -r backend/requirements-dev.txt
docker compose -p intellideploy-dev -f infra/compose.dev.yml up -d --wait postgres
```

数据库端口127.0.0.1:55432；开发库intellideploy_dev，测试库intellideploy_test。初始化脚本仅在新卷第一次启动时创建测试库；已有卷可检查后执行createdb，不删卷重建。

从backend/.env.example创建backend/.env，设置随机SECRET_KEY和实际所需配置。保留本地dev/test数据库地址，真实配置不提交。配置从backend/.env绝对路径读取；测试只接受专用intellideploy_test，禁止使用生产库。旧backend/intellideploy.db保留，不迁移或清空它。

```bash
PYTHONPATH=backend .venv/bin/python -m alembic -c backend/alembic.ini upgrade head
DATABASE_URL=postgresql+psycopg://intellideploy:dev-only@127.0.0.1:55432/intellideploy_test PYTHONPATH=backend .venv/bin/python -m alembic -c backend/alembic.ini upgrade head
PYTHONPATH=backend .venv/bin/python -m pytest tests/phase1 -q
```

正式API启动只核对迁移，不自动create_all。模型、云及支付缺配置不影响OpenAPI导出，但对应真实验收为NOT_RUN。

## 2. npm工作区与协议

根package-lock管理frontend、web和packages/api-client；两客户端保留各自React/框架版本。Worklets按原Expo锁文件固定兼容版本，不使用force忽略peer冲突。

```bash
npm ci
npm run api:generate
npm --workspace @intellideploy/api-client test
npm --workspace web test
npm --workspace web run typecheck
npm --workspace web run build
```

api:generate导出后端OpenAPI、生成TypeScript类型并构建ESM请求包。后端协议改变后重新执行；不要手改generated.ts。共享包当前覆盖01应用/任务/报告/下载接口，实例、能力、社区与额度方法随对应后端任务接入后扩充。

## 3. 启动入口

在web/.env.local设置：

```dotenv
API_BASE_URL=http://127.0.0.1:9000
WEB_ORIGIN=http://localhost:3000
SESSION_SECRET=替换为至少32字符的随机秘密
```

SESSION_SECRET只在Web服务器使用；浏览器会话是加密、HttpOnly cookie。生产配置HTTPS的WEB_ORIGIN，cookie为Secure。修改请求必须同源；BFF不允许浏览器选择任意上游URL。

四个终端分别运行：

```bash
npm run dev:api
npm run dev:worker
npm run dev:web
npm run dev:mobile
```

当前01阶段：dev:api提供新状态API；dev:web提供BFF，首页工作台在05-W1开发。dev:worker在03-D6的pipeline尚未实现时会明确退出，不认领或模拟完成任务。现有Expo可以启动，旧聊天链路已不在新API挂载，其屏幕在07-E2切换到新接口；请通过API测试当前状态能力。

浏览器API文档：http://localhost:9000/docs；Web地址：http://localhost:3000。Swagger注册/登录使用JSON，Authorize填Bearer token。POST /api/apps需Idempotency-Key，取得app_id/job_id后轮询GET /api/jobs/{id}。当前可验证持久化、归属、幂等、对话、取消和事件；没有生成引擎不能等待它自动交付。

WebBFF的/api/auth/login映射后端/auth/login，登录返回不含token；后续同源请求通过cookie认证。API/Expo直接使用/auth/login和Bearer。登录POST需正确Origin。

## 4. 手机与验证边界

手机EXPO_PUBLIC_API_BASE_URL需设为电脑局域网地址，例如http://192.168.1.10:9000；真机localhost是手机自身。Android标准模拟器可用http://10.0.2.2:9000，其他模拟器按网络配置；iOS模拟器通常可访问本机localhost。API监听0.0.0.0，系统防火墙需允许开发连接。生产使用HTTPS；浏览器预览额外来源需登记CORS_ORIGINS。

Expo55已支持npm工作区解析，沿用现有Metro/NativeWind配置；共享包先构建dist。原生客户端上线新链路后使用SecureStore，后台暂停轮询、回到前台回读同一任务。当前Expo网页导出通过不代表iOS/Android原生验收通过。

代码隔离执行/BuildKit、Linux/Sealos目标和TLS按外部清单登记后由对应任务接入；不能在本机API容器挂宿主Docker socket代替隔离节点。真实生成、两云、三支付和原生验收另保存证据，不把状态fixture或构建通过当成一期完成。
