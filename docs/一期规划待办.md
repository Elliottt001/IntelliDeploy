# 一期规划待办与开发入口

更新：2026-11-10。当前处于方案补齐阶段，尚未开始新流水线的代码实施。本文件记录产品完整性审查发现的缺口；不是已完成报告，也不改变已确认的一期范围。

产品决策：[PRD](PRD.md)。执行入口：[一期总计划](superpowers/plans/2026-11-09-phase1-00-roadmap.md)。用户可见交付：[一期交付与测试说明](一期交付与测试说明.md)。

## 1. 开发顺序

先补齐影响需求、生成、测试、部署衔接的方案，再执行主链路。01-F1/F2 的账号复用、数据库迁移、任务持久化与租约部分可先开发；涉及公开响应字段的部分仍须对照交付协议。07-E1 的协议客户端在01-F3完成后接入。界面基础联调可以使用标明fixture的测试数据，不把它算真实交付。

不要先把现有全部任务执行完再回头处理下列缺口：需求结构、测试运行环境、修复回路和实例生命周期会影响前面模块的接口。先定义这些接口及验收，再完成02/03/04的业务实现。社区与支付在主链路真实跑通后按依赖接入，但仍属于一期完整验收。

## 2. 尚未完成的方案补齐

以下每项关闭前，必须在对应子计划里写清输入/输出、实际执行步骤和可运行验收。仅勾选本文件不算完成。

- [ ] **P1 需求整理与变更规则**：从对话生成Requirement/AcceptanceItem，保存版本；少量业务追问；调整时保留旧要求并加入回归检查；无法实现的要求明确反馈。落点：01-F3、02-G4、03-D1。验收：原需求包含多个功能时不漏项，调整新增功能不破坏旧功能。
- [ ] **P2 候选运行与修复闭环**：隔离启动候选服务及依赖，获得测试地址，生成并执行核心检查；测试失败把实际证据送回Agent修复，重新验证；部署后的失败也按受控策略恢复/修复，保留旧发布。落点：02-G2/G4、03-D1/D5。验收：故意生成不能保存的笔记应用，系统自动发现、修复并在真实部署后验证，无人工启动或手动改代码。
- [ ] **P3 实例生命周期与持续计量**：补start/resume接口、真实状态核对、资源用量采集、欠费停机与恢复、失败资源清理；停止保留数据。落点：01-F2、03-D3/D4/D5、06-F1、05-W1、07-E2。验收：停机/欠费/补额度/恢复后原数据仍在，运行费用不重复计算，已删除实例不继续计运行费用。
- [ ] **P4 检索数据与运行兼容范围**：索引建立/更新/失效处理，实时检索降级规则与召回样本；明确A/B/C首批可执行的运行环境以及不支持时的自动处理。落点：02-G2/G3、03-D2/D3/D4。验收：已知合适项目被召回并优先复用；陈旧资料不能盖过实际源码证据；不兼容项目不伪造部署成功。支持四条路线不等于承诺执行所有语言和所有项目。
- [ ] **P5 平台生产部署与基本管理**：IntelliDeploy自身Web/API/Worker发布、迁移、健康与日志入口，登记目标资源、查看失败任务、配置价格和开发者权限；工作区/临时容器/未引用产物清理保护当前发布和用户数据。优先管理命令和现有后台能力，不先建设大型管理系统。落点：01-F1/F2、03、06-F4、07-E1/E3。验收：服务器重启后平台可恢复任务，管理员能定位失败；清理不删除当前版本、可恢复任务或持久数据。
- [ ] **P6 代表性评测与交付门槛**：建立超出四个示例的真实需求集，覆盖个人/多人、AI/搜索、现成复用、改造、整合和生成；记录功能覆盖、界面可用性、费用、耗时与失败类型。自动路线与强制路线分别统计，人工核对需求没有被模型自行缩减。落点：03-D1、07-E2/E3、06-F4。验收：所有必需项有证据；FAIL/NOT_RUN不能计为成功；对外成功率和耗时只引用实际评测。

关闭记录格式：`P编号；对应计划任务与提交；验收位置；剩余限制`。补方案时写实际计划提交，实施验收时再补代码提交和证据，区分“方案已写”和“功能已完成”。

## 3. 每次开发或换会话时

1. 先读PRD、总计划、本文件，再读本次子计划。
2. 核对所依赖的P项已经形成明确方案；涉及尚未明确的接口，先补该接口和验收。
3. 根据代码、Git状态和实际测试确定进度，不凭上次聊天中的“完成”判断。
4. 更新对应子计划的实施勾选及验证记录；遇到新缺口追加到本文件，并注明影响任务。
5. 一期完整完成要求所有必需业务、客户端、真实模型/两类云及支付验收通过；基础单元测试通过不代表一期完成。

## 4. 范围长期保留

一期：Expo手机平台客户端 + 新增Web + 共用API；A/B/C/D及优先检索复用；自动交付Web应用；继续对话调整；平台身份/数据/文件/AI/搜索；社区共享和独立副本；免费、套餐、购买额度与支付宝/微信/Stripe；基本托管运行。

二期：创作者变现、分成与提现；额外的运维保障和主动维护服务；长期委托式需求开发；生成原生手机应用与桌面程序。二期暂不写执行细节；不得把一期首次交付缺陷或基本运行能力挪入二期。
