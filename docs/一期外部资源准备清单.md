# 一期外部资源准备清单

更新：2026-11-10。用途：准备一期真实模型、执行、部署、客户端及支付验收所需资源。开发在 main 由本 agent 顺序进行，缺少外部配置时继续完成不依赖它的代码；缺配置的真实验收记为 NOT_RUN。

执行依据：[总计划](superpowers/plans/2026-11-09-phase1-00-roadmap.md)。这份清单是资料登记格式，不代表执行节点、部署器或支付功能已经实现。

## 1. 先准备哪些

| 优先级 | 准备内容 | 用在哪里 |
| --- | --- | --- |
| 第一批 | DeepSeek API Key、GitHub Token、可推送/拉取的镜像仓库 | 模型工具调用、真实检索、镜像构建 |
| 第一批 | 平台 Linux 主机、用户应用 Linux 部署目标、隔离执行节点；域名与解析权限 | 自动运行和验证应用、首条真实交付、平台上线 |
| 第二批 | Sealos kubeconfig、命名空间、存储和入口能力 | 同一应用在第二类目标真实部署 |
| 第二批 | 实际价格/套餐/免费额度与测试预算 | 受控执行、账本及托管用量验收 |
| 第三批 | 支付宝、微信支付、Stripe 商户及回调配置 | 三渠道购买、套餐和通知入账 |
| 第三批 | iOS/Android 设备或模拟器、客户端标识 | 原生平台客户端及跨端验收 |

不必一次提供所有内容。可以先告诉 agent 哪些已准备、哪些待准备，并给出本机登记文件路径。不要把明文 Key、密码、私钥或完整 kubeconfig 发到聊天里。

## 2. 保存和交接方式

建议在仓库外创建自己的私有配置目录，例如 `~/.config/intellideploy/`。目录权限设为 700，包含秘密的文件权限设为 600。SSH 私钥、kubeconfig、支付私钥和证书分别保存，登记文件只写它们的绝对路径。使用已有安全配置目录也可以。

```bash
mkdir -p ~/.config/intellideploy
chmod 700 ~/.config/intellideploy
```

模型和 GitHub 配置可以放在该目录的 `providers.env`。项目当前配置读取 `backend/.env`，后续 agent 会将所需配置接入正式配置键；**下文资源登记 YAML 不会被后端自动加载**。请勿把整份资源登记文件复制到 `backend/.env`。`backend/.env.example` 是可提交的配置样例，真实 `.env` 不提交。

交接时提供：登记文件的绝对路径、已准备的条目，以及允许验收使用的测试预算。agent 读取秘密用于配置时不打印文件内容，不将秘密写入 Git、日志或验收报告。

## 3. DeepSeek 与 GitHub

| 项目 | 需要提供 | 获取/核对方式 |
| --- | --- | --- |
| DeepSeek | 官方 API Key 的本机文件路径；API base URL；可用模型；账户有可用余额 | [DeepSeek 开放平台](https://platform.deepseek.com/)；账户可调用模型和价格在接入时重新核对 |
| GitHub | Token 的本机文件路径；使用的 GitHub 账号；是否只检索公开仓库 | [GitHub Token 设置](https://github.com/settings/tokens)；一期默认公开仓库检索，不需要组织管理、删除仓库等权限 |

DeepSeek 默认 base URL 为 `https://api.deepseek.com`。模型名称可先使用设计中的默认值，agent 接入时实测可用性；不要因供应商账户余额不足而误判用户平台额度不足。

建议 `providers.env` 内容如下，填写后设置文件权限 600：

```dotenv
DEEPSEEK_API_KEY=填入实际Key
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=填入账户当前可用模型
GITHUB_TOKEN=填入实际Token
```

该文件含秘密，只在本机保留。测试预算在第 9 节单独登记。

## 4. 镜像仓库

需要登记：

- registry 地址及完整命名空间，例如 `ghcr.io/你的账号/intellideploy`，或阿里云容器镜像服务的实际地址。
- 推送账号、推送凭据的文件路径；部署目标拉取凭据的文件路径。
- 镜像是否私有、允许保留多少测试镜像、仓库容量或收费限制。
- Linux、Sealos 和构建节点能否连接仓库；若为内网仓库，注明网络范围。

可使用已有 GHCR、阿里云 ACR 或其他 OCI 镜像仓库，无需新建自研服务。GHCR 推送权限需覆盖实际命名空间的 packages 写入，拉取权限需覆盖实际私有镜像；不要额外授予删除权限来做初期验收。

公网仓库应使用有效 TLS。自签仓库提供 CA 证书路径，不能默认关闭所有 TLS 校验。agent 将验证 push、digest 和两类目标 pull；只有登录成功不能证明镜像交付可用。

## 5. Linux 主机与隔离执行节点

请先登记三种角色，**角色不等于要求购买三台机器**；如果目前只有一台或两台，写清现有资源，由 agent 核对能如何安排。

| 角色 | 职责 | 需要的信息 |
| --- | --- | --- |
| 平台控制面 | 运行 Next.js Web、FastAPI、Worker、平台 PostgreSQL、Caddy | 主机地址、SSH端口/用户/私钥路径、系统/架构、CPU/内存/磁盘、部署根目录、sudo权限、现有服务与已占端口 |
| 用户应用部署目标 | 运行交付的应用及数据库等伴生服务 | 同上；另需 Docker/Compose、持久数据位置、允许使用的容量和应用域名后缀 |
| 执行/构建节点 | 运行生成代码、依赖安装、候选容器、浏览器验证和镜像构建 | 同上；是否独立主机、网络连接方式、可分配资源、是否已装容器环境/BuildKit |

第一批运行目标以 Linux amd64 CPU 为准。ARM主机、GPU、Windows等如有请注明，不能默认代替一期 amd64 目标。SSH账号需能在指定目录部署服务及管理对应容器；Docker组权限具有较高宿主权限，只交给平台可信部署程序，不能提供给生成代码。

执行节点与控制面必须有实际隔离，用户代码不得拿到控制面数据库管理凭据、云私钥或宿主管理 socket。**你不需要自己实现 runner 或 mTLS 服务**：先提供可用节点和网络信息，这些控制程序、证书接入和限制由开发任务落实。若已有执行服务，则提供端点地址、服务说明和客户端证书/私钥/CA的本机路径。

同时说明：哪些主机允许安装软件、修改防火墙/代理、使用测试目录；哪些已有服务必须避开。验收只使用明确登记的目标，平台不会自动购买或开通云资源。

## 6. 域名、DNS 和 HTTPS

需要登记：

- 平台 Web 域名，例如 `platform.你的域名`。
- 原生/API 域名，例如 `api.你的域名`。
- 用户应用域名后缀，例如 `apps.你的域名`，以及是否能配置 `*.apps.你的域名`。
- DNS 服务商、哪些记录已指向目标服务器、谁可以修改解析。
- 80/443 等入口端口的网络可达性；若使用 DNS challenge，提供受限 DNS Token 的本机路径。
- 若已有 TLS 证书，提供证书/私钥路径及续期方式；否则注明允许 Caddy 自动申请。

平台身份 cookie 与用户应用入口分开管理。支付通知需供应商能访问的公网 HTTPS 地址；不要先填写一个没有解析/没有服务的示例地址并视为就绪。Sealos若提供平台分配域名，也可以先登记其入口能力，不必强行使用自定义域名。

## 7. Sealos / Kubernetes

| 需要提供 | 说明 |
| --- | --- |
| kubeconfig绝对路径、context、namespace | 只给实际验收命名空间的所需权限；不要发送完整文件内容 |
| 集群地址与节点架构 | 本机/Worker能连接API，节点能拉取选定架构镜像 |
| 存储类名称、容量和访问模式 | 应用数据库/文件要能持久保存；记录namespace配额 |
| Ingress class、域名后缀、TLS方式 | 真实用户访问入口；需核对入口鉴权接法 |
| 镜像拉取方式 | 已有pull secret名称，或可用于创建secret的凭据引用 |
| 资源权限与限额 | Deployment、Service、Ingress、Secret、PVC及必要验证资源；CPU/内存/存储上限 |

可以直接从 Sealos 控制台取得当前命名空间的连接配置。只提供账号密码或网页地址不足以让部署器执行；agent会做RBAC、存储、入口及镜像拉取预检。只在登记namespace创建带平台标签的测试资源，不修改其他项目。

## 8. 三种支付渠道

### 支付宝

提供支付宝开放平台应用 `app_id`、商户/卖家 `seller_id`、网关环境（沙箱或生产）、应用RSA2私钥文件路径、支付宝验签公钥文件路径，以及是否已开通所需扫码支付产品。若使用证书模式，提供应用公钥证书、支付宝公钥证书、根证书路径并注明模式，接入时核对支持。

登记公网通知域名、可执行的测试方式。没有沙箱支持的产品不能用其他沙箱结果冒充该产品验收；生产小额交易需明确单笔和总测试金额。

### 微信支付

提供 `appid`、`mchid`、APIv3 Key文件路径、商户API证书序列号、商户签名私钥路径，以及平台验签证书或微信支付公钥材料及对应ID。注明已开通Native/H5等哪些支付产品、可使用的H5域名和通知域名。

桌面二维码与手机支付入口要分别核对：手机无法默认通过扫描自己屏幕上的二维码完成支付。agent依据已开通产品落实移动浏览器流程；没有H5能力时必须明确实际可用方式和限制，不能把Native二维码算作手机支付已通过。

微信支付不能假设具备与Stripe相同的完整test mode。没有可用测试环境时需经明确预算使用真实商户小额交易，或记录该项NOT_RUN。

### Stripe

提供test mode Secret Key文件路径、Webhook Signing Secret文件路径、服务端可用的price ID与对应商品/币种/金额/周期。测试卡和test mode用来验证购买、订阅、续期及通知；Webhook Secret是该实际endpoint或转发环境对应的secret，不能混用。

上线时另需live mode商户、Key、price ID和Webhook配置。test mode通过只表示集成验收，不能声称已能生产收款。

### 共用资料

三渠道需要：商品名称、金额与币种、授予额度、周期、退款/取消规则、支付回跳的登记平台域名。支付宝/微信一期套餐先按新订单手动续费；Stripe可自动订阅。不要把未授权的免密扣款当默认能力。

支付私钥、APIv3 Key和Stripe Secret仅服务端持有。浏览器返回成功页不能发额度；agent验收供应商通知、验签、金额/币种核对及重复通知一次入账。

## 9. 价格、免费额度与验收预算

需要你给出或标明“先使用测试政策，由成本测量后定价”：

- 新用户免费额度、周期免费额度、有效期和领取周期。
- 购买额度商品与订阅套餐：币种、金额、额度、周期，手动/自动续期。
- 平台额度的单位解释；模型、搜索、构建、计算、存储价格采用可版本化规则。
- 首轮真实模型/构建/托管总预算、单任务上限、重复质量评测预算。
- 生产支付验收允许的单笔金额及总金额；不允许真实扣款则写明。
- 用于验收的独立平台账号，不使用真实客户的私有数据。

没有正式售价不妨碍先做账本，但发生真实收费执行前必须有明确测试价格/预算。模型上游费用与用户平台用量分别记录，未知费用不填0。

## 10. 手机客户端验收

提供能使用的iOS模拟器/真机、Android模拟器/真机；若为真机说明系统版本、能否连接本机开发API或公网测试API。客户端的iOS bundleIdentifier、Android package可给出已有标识，或说明允许采用新的开发标识。

iOS真机开发构建可能需要Apple开发签名资料；模拟器不要求先准备付费商店发行账号。已有EAS项目则登记项目/账号配置位置；没有也不要求为测试先买发行服务。应用商店上线不是这份清单的前置条件。
